## 2024-08-24 - React Ref to State Conversion Missing Dependency Bug

**Learning:** When refactoring a React component by converting a `useRef` variable to a `useState` variable (often to fix a "Cannot access refs during render" error), it is extremely easy to forget to add the newly created state variable to the dependency array of any `useEffect` or `useMemo` hooks that rely on it. Because refs are mutable and persist across renders, they don't trigger re-renders or require inclusion in dependency arrays. State variables, however, do. If missed, effects will run with stale closures of the state variable, causing the component's logic to break or desync from the actual state.

**Action:** Whenever converting a `useRef` to a `useState`, systematically search the entire component file for all references to that variable. For every `useEffect`, `useCallback`, or `useMemo` that uses the new state variable, explicitly verify and update its dependency array to include the new state variable. Run linting (e.g. `pnpm lint`) specifically to catch `react-hooks/exhaustive-deps` violations after making the change.
