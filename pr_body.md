💥 The Bug: Next.js Server Actions return error objects rather than throwing exceptions. Therefore, appending `.catch()` to them inside a `useEffect` fails to catch any application-level errors, leading to a silent failure.
🔍 Root Cause: The `updateStreak` action is a Next.js Server Action that returns `{ error: '...' }` on failure, instead of rejecting the Promise. The `.catch()` block only handles true network exceptions, not returned error objects.
🛠️ The Fix: The hook call to `updateStreak` inside `StepFeedbackPanel.tsx` has been rewritten. We created an inner `async` wrapper function, explicitly `await`ed the call, and verified whether `result.error` is present.
🛡️ Prevention: Regression tests were added to `StepFeedbackPanel.test.tsx` to handle both mocked server error objects and actual network rejections for `updateStreak`, utilizing `waitFor` for resilience in CI instead of hardcoded timeouts.
